# Part 3 基础知识 — HTTPS

## 1. HTTPS 是什么？为什么需要它？

HTTP 本身不提供传输加密。如果直接通过不安全的 HTTP 连接提交账号密码、私人笔记等内容，链路上的第三方可能读取或篡改数据。

**HTTPS 是使用 TLS（Transport Layer Security）保护的 HTTP 通信。**

TLS 主要提供：

- **机密性**：使第三方难以读取传输的 HTTP 内容；
- **完整性**：检测传输内容是否被恶意修改；
- **服务器身份认证**：帮助客户端确定连接的是预期的网站。

HTTPS 保护的是传输过程，不意味着网站服务器自身的数据存储或权限设计自动安全。

## 2. 对称加密与非对称密码技术

### 对称加密

通信双方使用相同的秘密密钥加密和解密数据。优点是运算效率高，适合传输整篇笔记、图片、视频等大量内容；挑战是双方需要安全地获得共享密钥。

### 非对称密码技术

使用相互关联的公钥和私钥。公钥可以公开，私钥必须妥善保管。

非对称密码技术不只有“公钥加密、私钥解密”一种用途，也包含数字签名和密钥交换相关技术。HTTPS 需要通过这些机制验证服务器身份，并协商后续通信所使用的秘密。

非对称运算通常比对称加密昂贵，所以实际的大量应用数据主要用对称加密保护。

## 3. HTTPS 如何建立安全连接？

以现代 TLS 1.3 的常见完整握手为例，可以概括为以下步骤：

1. **开始 TLS 握手**：浏览器和服务器协商协议版本、加密算法等信息，并交换密钥协商所需的公开数据；
2. **密钥交换**：例如使用 ECDHE，双方分别保有自己的临时秘密信息，通过公开交换的数据计算出共享秘密，再派生通信密钥。共享秘密本身不必直接通过网络发送；
3. **验证服务器身份**：服务器提供数字证书及相应的握手证明；浏览器检查证书链、域名、有效期等，并验证服务器拥有与证书匹配的私钥；
4. **建立加密通信**：双方使用派生出的对称会话密钥和带认证的加密算法，保护后续 HTTP 请求与响应。

数字证书的作用是帮助建立可信的服务器身份，**不是直接加密每篇笔记的正文**。TLS 在不同协议版本与握手模式下存在细节差异，以上是便于理解的典型流程。

## 4. 数字证书怎样防止冒充服务器？

假设浏览器访问 `https://example.com`。

服务器提供的证书包含网站身份相关信息、公钥、有效期及签名等信息。浏览器会检查它是否与访问的域名匹配、是否由可信的证书链签发、是否处于有效期等，并结合握手验证服务器持有对应私钥。

如果攻击者试图冒充目标服务器，但不能提供可信的证书及对应的私钥证明，正常执行验证的浏览器就会拒绝建立可信连接或显示安全警告。

证书本身不能消除钓鱼网站风险：某个仿冒域名也可以拥有属于它自己的有效证书。因此还需要确认正在访问的网址正确。

## 5. HTTPS 能保护什么，不能保护什么？

在公共 Wi-Fi 上访问证书验证正常的 HTTPS 网站时，旁观者通常无法直接读取或修改加密的笔记正文和密码，但可能仍能观察到某些连接元数据，如目标 IP 地址、流量大小和时间。特定配置下的域名解析等信息也可能暴露；是否隐藏还取决于 DNS、ECH 等其他保护机制。

HTTPS 并不能代替：

- 用户身份认证和私人笔记的权限校验；
- 数据库安全、密码安全存储；
- 防范恶意服务器、钓鱼网站或已被控制的客户端设备。

## 6. 本阶段理解与实践情况

通过问答，已理解：大文件传输适合使用对称加密；TLS 握手通过密钥交换安全建立会话密钥；数字证书主要用于验证服务器身份；实际 HTTP 内容由会话密钥进行加密保护。

此前 FastAPI `/hello` 演示使用的是本地 HTTP，并未为该项目独立完成 HTTPS 证书部署或 TLS 抓包验证。本节为 HTTPS 原理学习；后续项目真正对外部署时再配置和检查 TLS。
