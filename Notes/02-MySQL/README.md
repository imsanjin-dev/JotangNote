# Part 2 后端常用技术栈 — MySQL

## 1. MySQL 是什么？

MySQL 是一种关系型数据库管理系统，使用表（Table）组织数据。表的列（Column）描述字段，行（Row）表示一条记录；主键（Primary Key）唯一标识记录。

对于 JotangNote，未来需要保存用户信息和笔记信息。例如：

| note_id | title | content |
| --- | --- | --- |
| 1 | Python 入门 | 学习变量与函数 |
| 2 | MySQL 基础 | 学习数据库索引 |

实际设计用户表时，不应明文存储密码，而应保存经过安全密码哈希处理的结果。

## 2. MySQL 可以存储多少数据？

MySQL 可以管理百万、千万乃至亿级记录，但没有脱离表结构、硬件、磁盘容量、索引、并发负载等条件的固定上限或性能保证。记录很多并不意味着所有查询都很快。

MySQL 不像普通 TXT 文件或 Excel 一样主要依靠人工处理整个文件。它提供数据库存储引擎、索引、缓冲池、查询优化器和事务等机制，以管理和查询大量数据。

## 3. 为什么查询能很快？索引有什么代价？

InnoDB 常见索引使用 B+ 树结构，可缩小要查找的数据范围；在条件合适时，不必把表中的每一行都扫描一遍。用主键查找一篇笔记，通常就能利用主键索引。

没有适用索引时，查询可能需要全表扫描；这不代表一定是在内存里逐条查找，数据页也可能从磁盘读取。

索引不是越多越好：

- 额外占用存储空间；
- 插入、删除和修改涉及的索引列时，可能增加维护成本；
- 是否能用索引取决于查询条件、索引设计和优化器的选择。

与哈希结构相比，B+ 树既适合精确查找，也擅长范围查找和按键排序；哈希通常擅长精确查找，但不能直接提供相同的有序范围访问。Redis 也不是“只靠 Hash 才快”，其性能还与主要以内存访问数据等因素有关。

## 4. 怎样用 Python 操作 MySQL？

Python 可以使用 PyMySQL 等数据库驱动连接 MySQL，创建游标（cursor）来执行 SQL，再读取查询结果。例如：

```sql
SELECT * FROM notes WHERE note_id = 2;
```

其中 `SELECT` 表示查询，`*` 表示返回全部列，`FROM notes` 指定表，`WHERE` 指定筛选条件。

连接数据库后，可以通过参数化查询传递用户输入：

```python
with connection.cursor() as cursor:
    cursor.execute(
        "SELECT * FROM notes WHERE note_id = %s",
        (note_id,)
    )
    result = cursor.fetchone()
```

`connection` 表示已经建立的数据库连接；`%s` 是驱动的参数占位符，并非自己用字符串格式化 SQL。驱动会把传入值作为数据处理，避免它改变 SQL 结构。

如果直接拼接用户输入 `1 OR 1=1`，可能产生：

```sql
SELECT * FROM notes WHERE note_id = 1 OR 1=1;
```

由于 `1=1` 为真，可能意外查询出所有行，这就是 SQL 注入风险。实际接口还应对笔记 ID 做类型验证、检查访问权限。
